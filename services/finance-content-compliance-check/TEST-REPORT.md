## Findings

error.** Case 4: `jurisdiction` as a number, `advice_boundary` as a string. Expected (test doctrine for
this program + the gateway's `invalid_input` mechanism in
`callpath.ts`): HTTP 422 `{ok:false, error:"invalid_input", field:...}`.
Actual: HTTP 200, verdict `NON_COMPLIANT` computed over the garbage values (0 pass / 1 fail / 31 missing; `jurisdiction_context_stated` failed on the numeric jurisdiction). The atom's handler does not validate
manifest field types before evaluation. Disposition: **fix spec filed** —
`verification/fix-specs/finance-content-compliance-check.md`. Retest on redeploy.

Gemini recomputed the declared spot checks from the full-pass input: `figures_evaluated=1`, `figures_incomplete=0` — both match the artifact.

Gemini's `expect.failing_checks` for the violations case named input field paths (`advice_boundary.personalized_recommendations_present`, …) rather than output check names; the three checks that actually failed correspond one-to-one to the planted violations, verified against the raw evidence — a naming imprecision in the case file, not an atom defect and not counted as a tester error.
