# Testing strategy regression pack — `testing-strategy-regression-pack`

**Deliverable type:** DELIVERABLE. This atom sells the deliverable it produces — a bounded judgment artifact — never the underlying knowledge itself.

## What it delivers

Bound capability (from the skill): Test at the right level for each risk — unit, integration, end-to-end — plus regression per defect and flake control.

A caller submits the inputs the bound skill works on and receives one deliverable back, in the contract's output shape (see `contract.yaml`). One unit of sale = one delivered result. In this atom's deterministic form, the caller submits a **declared testing strategy + regression plan record** and receives the audit verdict as the deliverable: the atom runs no tests, inspects no code and executes no suite (see Honest scoping).

## Buyer

First buyer hypothesis (from register data; not yet market-tested): teams and agents working in Engineering & code who need this deliverable on demand and would rather buy it per use than build or staff the capability themselves.

## Self-use (R3 — passed)

Our own workflow that calls it: **QA planning for product builds**. Wright is an internal caller on this atom (zero price, metered to the internal cost ledger — see `rails/billing.md`).

Twenty-one checks are computed from the declared rows, using
only the skill's own stated rules plus the consistency of the
declared record itself — no outside threshold is imported:

- **Risk rows declared:** the declared `risk_rows` list
  passes when it is present and names at least one risk. An
  absent list is missing evidence; an empty list fails — it
  declares no risk-first strategy at all.
- **Risk ids unique:** no declared `risk_id` may appear on
  more than one row.
- **Description per risk:** every declared risk row declares
  a non-empty `description`. A row with the field absent is
  missing evidence; a row declaring an empty description
  fails and is named in `risks_without_description`.
- **P0 status per risk:** every declared risk row declares
  its `is_p0` status. A row with the field absent is missing
  evidence and is named in `risks_without_p0_status`.
- **Test-level rows declared:** the declared
  `test_level_rows` list passes when it is present and names
  at least one row. An absent list is missing evidence; an
  empty list fails.
- **Test-level row ids unique:** no declared `level_row_id`
  may appear on more than one row.
- **Test level recognised:** every declared row's
  `test_level` is one of `unit`, `integration`, `e2e` — the
  three levels the skill names. Any other value fails and
  is named in `test_level_rows_with_invalid_level`.
- **Every level row's risk reference resolves:** every
  declared row's `risk_id` names one of the declared risks.
  A row with `risk_id` absent, or a record with the risk
  list absent, is missing evidence; a row naming an
  undeclared risk fails and is named in
  `test_level_rows_with_unknown_risk_reference`.
- **Every declared risk covered by a level row:** every
  declared risk is named by at least one level row. An
  uncovered risk fails and is named in
  `declared_risks_without_test_level_row`.
- **Every P0 risk covered by an e2e row:** every risk
  declared `is_p0: true` is named by at least one e2e row
  (the skill: P0 flows get e2e). A record declaring no P0
  risks passes this check vacuously. An uncovered P0 risk
  fails and is named in `p0_risks_without_e2e_row`.
- **Pyramid level counts in declared order:** the declared
  level-row counts follow the skill's stated order — at
  least one row per level, with unit rows >= integration
  rows >= e2e rows (many / fewer / few).
- **Declared changes declared:** the declared
  `declared_changes` list passes when it is present and
  names at least one change. An absent list is missing
  evidence; an empty list fails — it declares no regression
  scope at all.
- **Change ids unique:** no declared `change_id` may appear
  on more than one row.
- **Description per change:** every declared change row
  declares a non-empty `description`, named in
  `declared_changes_without_description` when empty.
- **Change kind recognised:** every declared change's
  `change_kind` is one of `feature`, `defect_fix`,
  `refactor` — the work kinds the skill names (feature
  build, bug fix, refactor). Any other value fails and is
  named in `declared_changes_with_invalid_kind`.
- **Regression rows declared:** the declared
  `regression_rows` list passes when it is present and
  names at least one row. An absent list is missing
  evidence; an empty list fails.
- **Regression row ids unique:** no declared
  `regression_id` may appear on more than one row.
- **Every regression row's change reference resolves:**
  every declared row's `change_id` names one of the
  declared changes, named in
  `regression_rows_with_unknown_change_reference` when not.
- **Every declared change covered by a regression row:**
  every declared change is named by at least one regression
  row. An uncovered change fails and is named in
  `declared_changes_without_regression_row`.
- **Every defect change covered by a regression row:**
  every `defect_fix` change is named by at least one
  regression row (the skill: every confirmed defect gets a
  regression test). A record declaring no defect changes
  passes vacuously. An uncovered defect change is named in
  `defect_changes_without_regression_row`.
- **Every regression row kept permanently:** every declared
  regression row declares `kept_permanently: true` (the
  skill: a regression test is kept forever). A row declaring
  it false fails and is named in
  `regression_rows_not_declared_permanent`.

One further check is gated on the record's own declared
gate field, following the skill's own conditional scope —
when the gate is declared `false`, the check passes as not
applicable; when the gate field is absent, the check is
missing evidence; when the gate is `true`, the target
declaration is required:

- **Quarantine ticket recorded:** a tracked ticket is
  required only where `flake_policy.known_flakes_present`
  is declared `true` (the skill's quality gate: no skipped
  or quarantined test without a tracked ticket).

The output also reports the computed `computed_status`
(`within_stated_limits_on_declared_evidence` /
`outside_stated_limits_on_declared_evidence` / null when any
of the twenty-one primary computed checks above cannot be
completed), `risk_rows_count`, `test_level_rows_count`,
`declared_changes_count` and `regression_rows_count` (the
declared list lengths, or null when a list is not declared —
counts are reported as integers, exactly), the per-level
counts `unit_level_row_count`,
`integration_level_row_count` and `e2e_level_row_count`,
the duplicate-id lists `duplicate_risk_ids`,
`duplicate_test_level_row_ids`, `duplicate_change_ids` and
`duplicate_regression_row_ids`, the row-name lists named in
the computed checks above, and the ratios
`risk_level_coverage_ratio` (declared risks covered by at
least one level row ÷ declared risks),
`p0_e2e_coverage_ratio` (P0 risks covered by an e2e row ÷
declared P0 risks), `change_regression_coverage_ratio`
(declared changes covered by a regression row ÷ declared
changes) and `defect_regression_coverage_ratio` (defect
changes covered by a regression row ÷ declared defect
changes). **Fixed serialization rule:** computed ratios are
reported as strings with exactly six decimal places,
produced in both implementations by the same rule — round
half up to 6dp, `floor(v * 1000000 + 0.5) / 1000000`, then
format with exactly six decimals. A ratio is null when its
denominator list is absent or empty (the P0 ratio is null
when no P0 risk is declared; the defect ratio is null when
no defect change is declared). That fixed serialization is
what makes the Python and TypeScript outputs byte-identical.

The skill states no numeric coverage threshold at all — its
demands are the pyramid's stated order, risk-first level
assignment, regression per defect, deterministic fixtures,
flake control, negative testing and honest gap reporting,
not bars the atom can set. Quantities are computed and
reported; the only bars on the computed rows are exact
coverage and consistency over the caller's own declared
rows, exactly as stated above. Declined thresholds, named:
a code-coverage percentage bar (the skill: coverage is a
signal, not a goal — no percentage is imported); a minimum
or maximum number of risks, level rows, changes or
regression rows beyond at least one each and the pyramid's
stated count order; a test-count-per-risk bar beyond one
covering level row (and one e2e row for P0 risks, as the
skill states); a suite runtime or speed bar; a flake-rate
bar; a defect-escape or pass-rate bar; any judgment that a
declared test is well designed, that a declared level is
the *right* level for a risk beyond the skill's stated
assignments, or that the strategy will in fact catch
defects (only that its declared record contains what the
skill requires).

The verdict is one of `TESTING_STRATEGY_SOUND` (all 58
checks pass), `TESTING_STRATEGY_NOT_SOUND` (any check
fails), or `INSUFFICIENT_EVIDENCE` (nothing fails but
evidence is missing), across eight sections:
scope_and_risk_declaration, test_levels_and_pyramid,
regression_coverage, fixtures_and_determinism, flake_policy,
negative_testing, entry_exit_and_reporting, red_lines.

## Honest scoping

This atom reviews a **declared** testing strategy +
regression plan record — it runs no tests, executes no
suite, inspects no code, opens no repository, measures no
coverage and verifies no test result against the world. A
strategy is sound *on the caller's declared evidence*: a
record that declares its risks covered, its regression rows
permanent and its suite green passes those checks even if
the real plan did none of it. It is a completeness and
consistency audit of the plan record the skill requires,
**not a testing service, a test execution, or a guarantee
that the software works**: it never judges whether a
declared test is well written, whether a declared risk is
the real risk, whether the declared levels will catch the
defects that matter, or whether the product should ship —
only that the record contains what the skill's method,
quality gates and red lines demand, and that its declared
rows are internally consistent.

Named exclusions and non-reducible parts (carried as caller
declarations only, never performed or judged): writing the
tests themselves; running any suite; designing individual
test cases (the `designed-test-case-pack` sibling's
ground); business acceptance testing and its sign-off (the
`uat-scenario-sign-off-pack` sibling's ground); fixing
defects or flakes; and measuring actual coverage — each is
EXCLUDED by name from this atom, which audits only the
declared record of those steps. Boundary cases, named: a
plan declaring no P0 risk passes the P0-e2e computed check
vacuously and reports a null P0 ratio (the atom does not
decide that a real P0 flow was misclassified — P0 status is
the caller's declaration); a plan declaring no defect
change likewise passes the defect-regression check
vacuously with a null defect ratio; the pyramid check
requires at least one declared row per level, so a
genuinely unit-only library plan cannot pass this record
format's pyramid check — such a plan is outside this
atom's computed reach, not failed on its merits.
