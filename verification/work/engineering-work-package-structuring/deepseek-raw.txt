## The one discrepancy

SERVICE.md states the revision-match check "is missing evidence when any transmittal lacks `document` or `revision`, or any document lacks `revision`." The document `Calc-001` has `revision: ""` — an empty revision string. Under the stated rule this makes the revision-match check **missing evidence**, so the list should be `null` (and the check status `missing`, not `fail`). The artifact instead reports `[]` and marks the check `fail`.

Two readings are possible:
- If "lacks revision" means the field is *absent* (not empty), then an empty string is a present-but-invalid revision, the check completes, and "B" ≠ "" is a genuine mismatch → `["NonExistent"]` and `fail`. Under this reading the artifact's `[]` is still wrong (it should list the mismatch), but the check status `fail` is right.
- If "lacks revision" includes empty string (consistent with the revision check treating empty as failing), the check is missing evidence → `null` and `missing`.

Either way the artifact's `[]` for `transmittals_with_revision_mismatch` does not follow from the stated rule: it is neither the mismatch list (`["NonExistent"]`) nor `null`. The artifact's `fail` status is defensible only under the first reading, but its empty list is not. This is a genuine disagreement between my recompute and the artifact on one computed quantity.
