## What SERVICE.md marks as computed

Two checks are computed from declared values, plus derived headline values:

1. **Zero warnings** — passes iff `warnings.warning_count == 0` (the skill's one stated number). Absent/non-number → missing evidence. Output `warning_count` = declared count, or `null`.
2. **Banned calls** — passes iff `bounds.banned_calls` contains none of `{gets, strcpy, sprintf, unchecked_scanf}`. Missing list → missing evidence; empty list → present, passes. Output `banned_calls_found` = stated entries found, in skill's stated order, or `null` if no list.
3. **`computed_status`** — `within_stated_limits_on_declared_evidence` if both computed checks pass; `outside_...` if either fails; `null` if either cannot be completed.
4. **`verdict`** — `REVIEW_SOUND` (all 30 pass), `REVIEW_DEFICIENT` (any fail), `INSUFFICIENT_EVIDENCE` (none fail, some missing).
5. **`summary`** — counts of pass/fail/missing over 30 checks.

The 30 checks = 5 (memory) + 6 (UB) + 2 (warnings) + 4 (bounds) + 7 (sanitizers) + 3 (portability) + 3 (build_and_test). Let me verify: 5+6=11, +2=13, +4=17, +7=24, +3=27, +3=30. ✓
