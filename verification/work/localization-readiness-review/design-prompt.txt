# Localization readiness review — `localization-readiness-review`

**Deliverable type:** REVIEW. This atom sells the review it produces — a bounded judgment artifact — never the underlying knowledge itself.

## What it delivers

Bound capability (from the skill): Internationalize properly — external strings, ICU formats, RTL, locale-aware everything, tested.

A caller submits the inputs the bound skill works on and receives one review back, in the contract's output shape (see `contract.yaml`). One unit of sale = one delivered result.

## Buyer

First buyer hypothesis (from register data; not yet market-tested): teams and agents working in Engineering & code who need this review on demand and would rather buy it per use than build or staff the capability themselves.

Several checks are computed from the declared rows, using only
the skill's own stated rules plus the consistency of the declared
record itself — no outside threshold is imported:

- **Locales declared:** the declared `locales` list passes only
  when it is present and non-empty; an absent list is missing
  evidence, an empty list fails.
- **Format tests per locale:** every declared locale row must
  declare `format_tests_passed: true` (the skill: "per-locale
  unit tests for formats"). A row with the field absent is
  missing evidence.
- **Direction per locale:** every declared locale row must
  declare `direction` from the skill's own distinction —
  `ltr`, `rtl`. A row with the field absent is missing evidence;
  a row declaring any other value fails and is named.
- **No locale code declared twice:** no declared `code` string
  may appear on more than one locale row. A row with `code`
  absent is missing evidence for this check.
- **Screenshots per locale:** every declared locale row must
  declare `screenshots_reviewed: true` (the skill: "screenshots
  of key screens per language on changes").

The output also reports the computed `computed_status`
(`within_stated_limits_on_declared_evidence` /
`outside_stated_limits_on_declared_evidence` / null when any of
the five primary computed checks above cannot be completed),
`locales_count` (the declared list length, or null when the list
is not declared — counts are reported as integers, exactly),
the row-name lists `locales_without_format_tests` (locales whose
field is present but not true; a locale with the field absent is
missing evidence and does not appear),
`locales_with_invalid_direction` (locales whose `direction` is
present but not in the skill's distinction),
`duplicate_locale_codes` (locale codes declared on more than one
row, in the order their second occurrence appears) and
`locales_without_screenshots` (locales whose field is present
but not true), and the three coverage ratios
`format_test_coverage` (locales passing format tests ÷ declared
locales), `valid_direction_coverage` (locales with a valid
direction ÷ declared locales) and `screenshot_coverage`
(locales with screenshots reviewed ÷ declared locales).
**Fixed serialization rule:** computed ratios are reported as
strings with exactly six decimal places, produced in both
implementations by the same rule — round half up to 6dp,
`floor(v * 1000000 + 0.5) / 1000000`, then format with exactly six
decimals; comparisons use the unrounded values. A ratio is null
when its denominator list is absent or empty. That fixed
serialization is what makes the Python and TypeScript outputs
byte-identical.

The skill states no numeric pass/fail threshold — no coverage,
count or expansion bar: its targets are qualitative attestations
the record declares addressed, not bars the atom can set.
Quantities are computed and reported; the only bar on the
computed rows is completeness over the caller's own declared
rows, exactly as stated above. Declined thresholds, named: a
translation-coverage or string-externalization percentage; a
number of locales or languages a product must support; a number
of externalized strings or stable keys; a format-test count or
test-coverage percentage; a screenshot or key-screen count; a
text-expansion percentage to pass (the skill's stated +30–100%
language length variance is a layout attestation the record
declares allowed, not a measured bar this atom sets); a
pseudo-localization elongation percentage; a number of RTL
locales beyond the skill's stated one RTL smoke locale if in
scope; a glossary term count; a translation-quality,
machine-translation-quality or human-review turnaround score; a
coverage percentage below completeness.

The verdict is one of `LOCALIZATION_READINESS_SOUND` (all 37
checks pass), `LOCALIZATION_READINESS_NOT_SOUND` (any check
fails), or `INSUFFICIENT_EVIDENCE` (nothing fails but evidence
is missing), across five sections:
externalized_strings_and_translation_units,
locale_formats_plurals_and_grammar,
flexible_layout_and_rtl_readiness,
content_workflow_and_glossary, locale_testing_and_red_lines.

## Honest scoping

This atom audits a **declared** localization record — it
inspects no source code, runs no lint or pseudo-localization,
renders no screen, executes no format test, and does not verify
that a declared control actually works. A record is sound *on
the caller's declared evidence*: a manifest that declares all
strings externalized, formats via locale APIs and no raw
machine translation shipped unreviewed passes those checks even
if the real product does none of it. It is a completeness and
consistency audit of the record the skill requires, **not a
translation service, a localization service, or a certification
that a product is correctly localized in any language**: it
never judges whether a translation is accurate or idiomatic,
whether a format renders correctly for a locale, whether a
layout truly survives a language, or whether a glossary term is
the right term — only that the record contains what the skill's
sections and red lines demand, and that its declared rows are
internally consistent.

Named exclusions and non-reducible parts (carried as caller
declarations only, never judged): no numeric thresholds beyond
the skill's own stated rules (see the declined list above); no
live verification of any declared fact; no text inspection —
hardcoded strings, string concatenation and unreviewed machine
translation are caller-declared present/absent flags, the atom
reads no code or copy; translation quality and linguistic fit
are caller declarations — the atom checks only that workflow,
glossary, testing and per-locale rows are declared and
consistent; whether RTL is in scope for a product is a caller
declaration — the smoke-locale check reads the declared flag
only.
