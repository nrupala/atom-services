# Delivery plan preparation — `delivery-plan-preparation`

**Deliverable type:** DELIVERABLE. This atom sells the deliverable it produces — a bounded judgment artifact — never the underlying knowledge itself.

## What it delivers

Bound capability (from the skill): Plan and run delivery in phases — plan gates, milestones, risk register, decision log, and honest status.

A caller submits the inputs the bound skill works on and receives one deliverable back, in the contract's output shape (see `contract.yaml`). One unit of sale = one delivered result.

## Buyer

First buyer hypothesis (from register data; not yet market-tested): teams and agents working in Engineering & code who need this deliverable on demand and would rather buy it per use than build or staff the capability themselves.

Most checks are computed from the declared rows, using only the
consistency of the declared record itself and schedule
arithmetic over the declared dates — no outside threshold is
imported:

- **Phases declared:** the declared `phases` list passes only
  when it is present and non-empty; an absent list is missing
  evidence, an empty list fails.
- **Owner per phase:** every declared phase row must name an
  owner (a non-empty `owner` string). A row with the field
  absent is missing evidence; a row naming an empty string
  fails.
- **Exit criteria per phase:** every declared phase row must
  declare `exit_criteria_declared: true` (the skill's quality
  gate: every phase has exit criteria and an owner). A row with
  the field absent is missing evidence.
- **Size per phase:** every declared phase row must carry a
  size from the skill's own vocabulary — `S`, `M` or `L` (the
  skill's "sizes (S/M/L)"). Any other string fails; a row with
  the field absent is missing evidence.
- **Phase dates valid and in order:** every declared phase row
  must carry a `start_date` and an `end_date` that parse as
  strict ISO calendar dates, with the end not before the start.
  An unparseable or impossible date fails.
- **Dependencies resolve:** every name in a phase's declared
  `depends_on` list must name a declared phase (matched on the
  phase rows' `name` strings). An unresolvable name fails and
  is reported in `unknown_dependencies` as
  `dependent->dependency`.
- **Dependencies precede dependents:** schedule arithmetic over
  the declared dates — a dependency's declared `end_date` must
  not fall after the dependent phase's declared `start_date`.
  A violation fails and is reported in
  `dependency_order_violations` as `dependent->dependency`.
  The check is missing evidence when any phase row lacks a
  `depends_on`, `start_date` or `end_date` field, or a named
  phase lacks an `end_date`.
- **Milestones declared:** the declared `milestones` list
  passes only when it is present and non-empty.
- **Milestone phase resolution:** every declared milestone's
  `phase` string must name a declared phase; an unresolvable
  name fails and is reported in
  `milestones_with_unknown_phase`.
- **Owner per milestone:** every declared milestone row must
  name a non-empty `owner` string, on the same rule as phases.
- **Milestone due within phase dates:** schedule arithmetic —
  every milestone's declared `due_date` must parse and fall
  within its named phase's declared start and end dates,
  inclusive. A milestone due outside, or with an unparseable
  due date, fails and is reported in
  `milestones_due_outside_phase_dates`. The check is missing
  evidence when any milestone lacks `phase` or `due_date`, or
  any phase lacks `start_date` or `end_date`.
- **Assumptions per phase:** every declared phase row must
  declare `assumptions_declared: true` (the skill: sizes come
  with assumptions listed).
- **Risks declared:** the declared `risks` list passes only
  when it is present and non-empty.
- **Mitigation and trigger per risk:** every declared risk row
  must declare `mitigation_declared: true` and
  `trigger_declared: true` (the skill's quality gate: risks
  have triggers and mitigations).
- **Decisions declared:** the declared `decisions` list passes
  only when it is present and non-empty.
- **Decision entry completeness:** every declared decision-log
  entry must carry the skill's log shape — a `date` that
  parses as a strict ISO calendar date, a non-empty `decision`
  string, `rationale_declared: true` and
  `alternatives_declared: true`. An incomplete entry fails and
  is reported in `decisions_incomplete` under its `decision`
  text.

The output also reports the computed `computed_status`
(`within_stated_limits_on_declared_evidence` /
`outside_stated_limits_on_declared_evidence` / null when any of
the six primary computed checks — phases declared, owner per
phase, exit criteria per phase, dependencies resolve, phase
dates valid and in order, dependencies precede dependents —
cannot be completed), the counts `phases_count`,
`milestones_count`, `risks_count` and `decisions_count` (the
declared list lengths, or null when the list is not declared —
counts are reported as integers, exactly), the row-name lists
`phases_without_owner`, `phases_without_exit_criteria`,
`phases_with_date_problems`, `unknown_dependencies`,
`dependency_order_violations`, `milestones_without_owner`,
`milestones_with_unknown_phase`,
`milestones_due_outside_phase_dates`,
`risks_without_mitigation`, `risks_without_trigger` and
`decisions_incomplete` (each null when its underlying list —
or, for the milestone-phase lists, either list — is not
declared), `total_duration_days` (the exact integer day count
from the earliest declared phase start to the latest declared
phase end; null unless every declared phase carries both dates
and both parse), and the three coverage ratios
`owner_coverage` (phases naming an owner ÷ declared phases),
`dependency_coverage` (dependency references naming a declared
phase ÷ declared dependency references) and
`milestone_phase_coverage` (milestones naming a declared phase
÷ declared milestones).
**Fixed serialization rule:** computed ratios are reported as
strings with exactly four decimal places, produced in both
implementations by the same rule — round half up to 4dp,
`floor(v * 10000 + 0.5) / 10000`, then format with exactly four
decimals; comparisons use the unrounded values. A ratio is null
when its denominator list is absent or empty (and, for
dependency coverage, when no phase declares any dependency;
for milestone phase coverage, when either list is absent).
That fixed serialization is what makes the Python and
TypeScript outputs byte-identical.

The skill states no numeric threshold — no WIP number, no
phase, milestone, risk or decision count, no confidence scale,
and no duration limit — so no numeric threshold check is
invented. Quantities are computed and reported; the only bar
on the computed rows is completeness and internal consistency
over the caller's own declared rows (every declared phase,
milestone, risk and decision entry), exactly as stated above.
Declined thresholds, named: a numeric WIP limit (the skill
says "finish phases; don't parallelize beyond capacity" and
states no number — only that a limit is declared is checked);
a minimum or maximum phase count; a minimum or maximum
milestone count; a minimum risk-register size; a minimum
decision-log entry count beyond non-empty; a confidence scale
or percentage (the skill requires confidence be *reported*,
and names no scale, so only that declaration is checked); a
maximum total plan duration or phase duration; an estimate
accuracy tolerance (the skill requires honest sizes with
assumptions, not a variance bound).

The verdict is one of `DELIVERY_PLAN_READY` (all 38 checks
pass), `DELIVERY_PLAN_NOT_READY` (any check fails), or
`INSUFFICIENT_EVIDENCE` (nothing fails but evidence is
missing), across four sections: framing_and_approval,
phases_milestones_and_dependencies,
risks_estimates_and_decisions,
execution_discipline_and_status.

## Honest scoping

This atom audits a **declared** delivery plan record — it
writes no plan, sequences no work, estimates nothing, reads no
`PLAN.md` / `RISKS.md` files or project trackers, and does not
verify that a declared control actually happens. A plan is
ready *on the caller's declared evidence*: a manifest that
declares an approved plan, owned phases with exit criteria,
and mitigated risks passes those checks even if the real
project has none of it. It is a completeness and consistency
audit of the record the skill requires, **not a project
management service or a delivery certification**: it never
judges whether the goal is the right goal, whether the phases
are the right decomposition, whether a size is honest, whether
a mitigation would actually work, or whether the reported
confidence is warranted — only that the record contains what
the skill's method, quality gates and red lines demand, and
that its declared rows are internally consistent over the
declared dates.

Non-reducible parts, named — these remain caller declarations
only, and the atom states plainly that it does not judge them:
whether the goal and deliverable are the right ones; whether
the constraints list is complete for the real project; whether
an exit criterion is strong enough to gate on; whether a size
estimate is honest or accurate (only that a size from the
skill's vocabulary and declared assumptions are present);
whether the flagged least-known item truly is the least known
(only that the flag is declared); whether a risk's mitigation
or trigger is adequate (only that both are declared); whether
a decision's rationale is sound or its alternatives were
genuinely considered (only that both are declared, in an
append-only log shape); what the caller's actual capacity is,
and therefore what WIP limit is right (only that a limit is
declared); and whether the reported status and confidence are
honest rather than status theater (only that phase, done,
next, blockers and confidence are all declared reported).
Named exclusions: no numeric thresholds (see the declined
list above); no critical-path computation beyond the declared
dependency-order arithmetic (the skill requires dependencies
and sequencing be planned, and states no critical-path
method); no check that a phase's dates are realistic; no live
verification of any declared fact.
