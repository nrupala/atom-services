### Named Conduit gaps (from reading ~/workspace/conduit)

- **G1 — No self-serve signup / key issuance.** Conduit's live gate
  checks one static comma-separated `CONDUIT_API_KEY` secret.
- **G2 — No per-user, per-atom keys.** One shared key namespace for
  the one live connector; atoms need per-atom HMAC issuance +
  verification (design + reference implementation exist here).
- **G3 — No metering→billing.** Tool calls are logged with
  `key_hash` only; no usage ledger. Conduit ADR-0004: M1/M2 carry
  no payment code.
- **G4 — No balance/packs store.** The billing core (Conduit M4) is
  unbuilt; prepaid balance + drawdown does not exist yet.
- **G5 — No per-key rate limiting.** Conduit's architecture lists
  shared rate limiting + KV metering as not-yet.
- **G6 — No multi-service hosting pattern.** Each connector is its
  own Worker; atoms need per-atom Workers from a shared template or
  one atoms gateway Worker routing `/mcp/<atom>` — undecided, unbuilt.
- **G7 — No internal-caller ledger (R2).** Internal calls cannot yet
  be metered to a cost ledger distinct from external usage.
- **G8 — Listing ops at scale.** 162 atoms = 162 registry
  submissions (or a gateway listing decision); no submission process
  exists yet beyond Conduit's single hand-filed `server.json`.
