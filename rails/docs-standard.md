# Rails — Docs standard

Every atom unit in `services/<service-name>/` carries the same five
documents plus a listing package. The standard exists because of the
owner's 2026-10-17 ruling: an atom is not a loose catalogue item — it
ships with its growth, retention, and maintenance documents in place,
in proper structure, so it can be updated and realized suitably.

## The five documents

| File | Carries | Rule |
|---|---|---|
| `SERVICE.md` | What the atom delivers (the artifact type — verdict/check/map/stamp/report — never the raw knowledge), the buyer hypothesis, the R3 self-use workflow, the pricing unit, status, the register's named doubt | Buyer and self-use come from the register entry; a doubt in the register is printed, never hidden |
| `contract.yaml` | The machine contract: name, tier, status, binding (skill name/path/version, R1 rule), deliverable type, endpoints, **keys** (namespace + prefix + issuance), **rate_limit**, **pricing** (unit, rate, rate_status per the protocol in `billing.md`), self-use, qualification tests | `rate` stays null until the pricing protocol produces one; `status` moves scaffolded → built → gated → live only on evidence |
| `growth.md` | Seed demand (our own workflow), channel shape per tier (A: Conduit + endpoint + registry sweep; B: packs only), the no-spend-until-measured rule | Specific to the atom's register data, not boilerplate |
| `retention.md` | Why a caller calls again (per pricing-unit cadence), our own repeat-use pattern, the churn signal read at 30/60/90 days | Names the refine/reprice/retire response |
| `maintenance.md` | The R1 binding in operational form, the refinement loop, status, and the atom's test record | Test results are recorded here when tests exist, with the run date and command |

## The listing package

`listing/server.json` + `listing/listing.md`, in Conduit's listing
shape (Official MCP Registry `server.json`, as Conduit's own
`registry/server.json`). The listing states: which atom it is, what
it delivers, that it has its own API key and how a user gets one, its
endpoints, and its rate with `rate_status`. A scaffolded atom's
listing is a **stub** and says so in its `_meta` — a stub is never
submitted to any registry.

## Regeneration

`registry/PUBLIC-LIST.md` and all scaffolds are generated by
`tools/generate.py` from `registry/register.yaml`. Edit the register,
re-run the generator, commit both. Files containing `HAND-BUILT` are
never overwritten by the generator — that is how built-out atoms
(atom #1 first) keep their hand-written documents.
